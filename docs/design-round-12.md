# Design memo — round 12 (diagram CLI + generated README)

Phase 1 output, 2026-06-10. Two CLI additions on the existing `prism` tool:
a `diagram` subcommand (render the round-10 builders from the shell), and a
`gen`-time GitHub-flavoured `README.md` so generated stubs ship with in-UI
diagrams and field docs. Both reuse existing pieces — the diagram builders,
`_resolve`, `_discover`/`_build_workset` — and emit text only.

## Feature A — `prism diagram`

```
prism diagram {scope|projection|refs} [PATH ...]
               [--format {mermaid,dot,d2,json}] [--output FILE] [--direction {TD,LR}]
```

- `scope [PATH ...]` — `scope_diagram(*scopes)`; PATHs are `module:Scope`. None =
  every declared scope.
- `projection PATH` — `projection_diagram(Model)`; exactly one `module:Model`.
- `refs PATH` — `Model.__refs__.diagram()`; exactly one `module:Model`.
- `--format` default **mermaid**; `json` → `as_dict()` via `json.dumps(indent=2)`.
- `--output` writes a file; default prints to **stdout** (pipe to mermaid-cli /
  dot / d2). `--direction` defaults `TD`.

Reuses `_resolve` for paths; inserts CWD on `sys.path` so the target package
imports. A path of the wrong kind (a Scope where a model is wanted, or vice
versa) raises a clear `CodegenError` (exit 2).

## Feature B — generated `README.md`

When generating reflected models, also write a GitHub-flavoured markdown doc
(GitHub renders ```mermaid fenced blocks natively, so the diagrams are visible
in-UI). It documents exactly the generated workset.

**Trigger.** Config `[tool.pydantic-prism] readme = "GENERATED.md"` (relative to
the pyproject, like `output`), and/or a `prism gen --readme PATH` override. If
set, `gen` writes both stub and README; **`prism check` verifies both** (same
drift discipline — a stale README fails CI). If neither, no README.

**Content** (grouped by source canonical model, reflecting the workset):

```
# Generated models — <module>
<!-- generated by `prism gen` — do not edit -->

## Scopes
```mermaid
<scope_diagram over all scopes used>
```

## <Model>           (+ docstring)
```mermaid
<projection_diagram(Model)>
```
### <Projection>  (scope `<token>`)
| field | type | description |
...field rows from NodeField...

### Relationships   (only if the model has ref/embedded edges)
```mermaid
<Model.__refs__.diagram()>
```
```

Diagrams are **Mermaid** (the only format GitHub renders inline); the round-11
`NodeField` metadata feeds both the diagrams and the description tables. The
README is a generated artifact — do-not-edit banner; regenerated, not hand-edited.

## Q1. `diagram` subcommand shape

Options: `prism diagram {scope|projection|refs} [PATH] --format/--output/--direction`
(recommended) / a flag-per-kind / separate `prism scope-diagram` etc.
**Recommend the single `diagram` verb with a kind argument** — one discoverable
subcommand, format/output/direction shared. `json` emits the lossless IR.

## Q2. README trigger & `check`

Options: config `readme=` + `--readme` override, verified by `check`
(recommended) / `gen --readme` only (no config, not checked) / a separate
`prism readme` command.
**Recommend config + `--readme`, checked.** It mirrors `output`'s story exactly
(persistent config, CLI override, drift-verified), so README staleness is a CI
failure like stub staleness — which is the whole point of shipping docs with the
code.

## Q3. README content depth

Options: scopes + per-model projection diagram + refs diagram + per-projection
field/description tables (recommended) / diagrams only / tables only.
**Recommend the full set.** Diagrams give the shape (rendered in-UI), tables give
the searchable field docs (name/type/description) — together they are the
"diagrams and docs" the request asks for. Reflect the generated workset (group
projections by `__prism_source__`), not an unrelated full enumeration.

## Q4. Confirmations (fiat)

- README diagrams are **Mermaid only** (GitHub renders nothing else inline).
- `diagram` defaults: `--format mermaid`, stdout, `--direction TD`.
- Both new outputs carry a do-not-edit banner; `check` covers the README when
  configured.
